# Smart Ticketing System – Backend + WinForms demo

Target: **Visual Studio 2026 / .NET Framework 4.7.2**, four existing projects preserved.

## Setup
1. Install SQL Server 2019+ (or compatible SQL Server Express) and SQL Server Management Studio.
2. Execute `database/01_create_schema.sql` in SSMS on your instance (fresh database only). Then execute `database/02_seed_data.sql` and `database/03_late_success_transition.sql` in that order.
3. In `SmartTicketingSystem/App.config`, change `Data Source` to your SQL Server instance name, e.g. `.\\SQLEXPRESS` (check local server name).
4. Open `SmartTicketingSystem/SmartTicketingSystem.slnx` in Visual Studio, set `SmartTicketingSystem` as Startup Project, **Build Solution**, run F5.
5. Choose route → Start purchase → choose CARD or QR → choose APPROVED/DECLINED/NO_RESPONSE → Pay.
6. For DECLINED select Retry once, then Pay again; for NO_RESPONSE the record remains PENDING and no retry is offered. The test button "Reconcile: late success" simulates a verified late gateway success.

## Architecture
- `SmartTicketing.Models`: Route, PurchaseSession, PurchaseTransaction, PaymentAttempt, Ticket and statuses.
- `SmartTicketing.Data`: parameterized ADO.NET SQL commands, locking and persistence.
- `SmartTicketing.Services`: PricingEngine, TVMController, PaymentProcessor, GatewayAdapter, ReconciliationService, PrinterService.
- `SmartTicketingSystem`: demonstration WinForms UI (runtime layout, original Form1 retained untouched).

## Caution: demo vs production
- **Card/QR gateway is MOCK only**. The QR payload is a demo string, **not a bank-scannable QR**. No payment information or secrets are sent to payment platforms.
- The QR expiry is an explicit action in the demo; a real timer/webhook/verification is still required for production.
- `NO_RESPONSE` immediately simulates a 30-second timeout (does not literally wait 30s).
- Reconciliation is a manual simulation; there is no real background worker, scheduled status inquiry, webhook verification or retryable outbox in this build.
- Printer output is simulated; it does not send a barcode to a physical device.
- The app is demonstration-level software, NOT a production payment platform.
- The file `01_create_schema.sql` is the user's original; use on a fresh database because it includes CREATE statements.

## Suggested tests
1. CARD APPROVED => COMPLETED and one Ticket row.
2. CARD DECLINED => FAILED and no Ticket; Retry once (new TransactionId, same SessionId).
3. QR EXPIRED => EXPIRED; retry allowed once.
4. NO_RESPONSE => PENDING, support reference, no retry; late SUCCESS => PAID_UNFULFILLED, no ticket.
5. APPROVED + simulate printer failure => PAID_UNFULFILLED and TVM blocked.
6. Do not send a second payment using same TransactionId after COMPLETED.
